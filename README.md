| 主线 | 学习内容 | 最小交付 |

## 工作区定位

这里是**学习过程、证据和面试资料的总索引**，不是新的 SLAM 源码仓库，也不是大数据存储位置。

- 源码保持原仓库；此处只记入口路径、commit、配置、运行命令和结论。
- 每篇论文记录问题、公式、实现、证据和缺陷，不只抄摘要。
- 实验必须能追溯到数据集/序列、配置、版本、设备和日志；未运行的方案标注“计划”，失败结果也保留。
- 简历中的每个数字必须能指向实验记录。没有设备验证就不要写“已端侧部署”。
- 不自动修改 `D:\Xuxp\ORB_SP_FBoost_SLAM3_pano` 等现有研究仓库。

## 从今天开始：只做四件事

1. 打开 `00_planning/current_status.md`，逐项更新为**已完成/在做/未开始/待核验**；不要假定此前计划已经落地。
2. 根据岗位选择 `04_projects/` 的一个深入项目；已有 VI-SLAM 工作先核验路径、commit 和实验，新增方向从小型基线开始。
3. 从 `02_papers/paper_index.csv` 选择当前主线的一篇 P0/P1 论文，将 `02_papers/paper_note_template.md` 复制到对应分类目录精读；配合 `03_exercises/` 实验。
4. 把 `06_weekly/weekly_template.md` 复制为本周文件（例如 `2026-W45.md`），写下最多三项本周核心交付物。

## 最小工作流（每次学习 3 分钟记录）

- **学到了什么**：一个具体概念、公式或代码路径。
- **做了什么**：读了哪一节、运行了哪个 commit、保存了哪个日志。
- **证据是什么**：笔记链接、命令、图表或测试结果。
- **还不确定什么**：假设、失败或未验证点。
- **下次做什么**：一项能够执行的下一步。

每周只更新 `06_weekly/`，每次重要实验只更新 `05_experiments/results_index.csv`；避免在许多位置重复维护相同进度。

## 关于版本控制与大文件

这个目录适合单独 `git init`，但大数据、模型权重、视频、build、缓存和运行日志不应直接提交。建议大型实验工件仍保留在源仓库或专用存储路径，在此记录可访问的相对/绝对路径、哈希和实验条件。
